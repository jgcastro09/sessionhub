# TASK-0004 — Implementar Media Manager e Collect Project

## Summary

Criar um gerenciador central de arquivos do projeto com auditoria de mídias, reconexão de assets offline, coleta portátil e integração segura com o Hot Backup.

## Detailed Description

<!-- task-board:description:start -->
Implementar um sistema central de gerenciamento de todos os arquivos utilizados pelo projeto, composto por Media Manager, suporte a mídias offline, reconexão de arquivos e Collect Project.

Adicionar na Top Bar, imediatamente depois das informações de FPS da interface e resolução, um botão compacto chamado `Media`.

Ordem visual:

```text
Interface FPS | Resolução | Media
```

O botão deve seguir o padrão visual existente e abrir o modal `Media Manager`.

O Media Manager deve listar e permitir auditar todos os arquivos relacionados ao projeto, incluindo:

* vídeos;
* imagens;
* sequências de imagens;
* áudios;
* LUTs;
* modelos e texturas 3D;
* mappings;
* layouts;
* configurações e perfis de controladoras;
* MIDI mappings;
* presets;
* demais arquivos externos necessários para reconstruir o projeto.

Cada item deve apresentar, quando disponível:

* nome;
* tipo;
* extensão;
* status;
* caminho atual;
* caminho relativo;
* último caminho conhecido;
* tamanho;
* hash;
* data de modificação;
* quantidade e locais de uso;
* indicação de arquivo interno ou externo ao projeto;
* estado de sincronização com o Hot Backup.

O modal deve possuir filtros por tipo e estado, pesquisa e ações para:

* localizar arquivo;
* localizar pasta;
* reconectar;
* substituir;
* reconectar todos;
* revelar no Explorer ou Finder;
* abrir o local onde o arquivo está sendo utilizado;
* validar integridade;
* executar `Collect Project`.

Criar um registro central de assets. Clips, Nodes e demais sistemas não devem depender apenas de caminhos absolutos armazenados diretamente.

Cada arquivo deve possuir um `Asset ID` estável, preservado mesmo quando:

* o projeto for movido;
* a pasta for renomeada;
* o arquivo for reconectado;
* o projeto for coletado;
* o projeto for aberto em outra máquina;
* Primary e Backup utilizarem diretórios diferentes.

O registro de cada asset deve armazenar:

```text
Asset ID
Tipo
Nome
Extensão
Caminho relativo
Caminho absoluto atual
Caminho absoluto original
Último caminho conhecido
Tamanho
Hash
Data de modificação
Metadados
Status
Referências
Estado de backup
```

Os consumidores devem referenciar prioritariamente o Asset ID. A resolução física do arquivo deve ficar centralizada em um Asset Manager ou serviço equivalente.

Cada projeto deve possuir um `Project Root` dinâmico, definido pela pasta onde o arquivo principal `.nstage` estiver localizado.

Exemplo:

```text
Desktop/
└── MeuEvento/
    ├── MeuEvento.nstage
    ├── Media/
    ├── Mapping/
    └── Controllers/
```

Ao abrir `MeuEvento.nstage`, a pasta `MeuEvento` deve se tornar automaticamente o Project Root.

O usuário deve poder mover a pasta para Desktop, SSD externo, NAS ou outra máquina e abrir o projeto diretamente, sem importar ou copiar arquivos para uma pasta fixa do NodeStage.

A resolução de cada asset deve seguir esta ordem:

```text
1. Caminho relativo ao Project Root
2. Caminho relativo registrado no projeto ou manifesto
3. Subpastas internas conhecidas
4. Caminho absoluto atual
5. Caminho absoluto original
6. Localização anterior registrada
7. Correspondência por Asset ID
8. Correspondência por hash
9. Nome + extensão + tamanho
10. Offline
```

Subpastas internas conhecidas:

```text
Media/
Mapping/
Controllers/
Presets/
LUTs/
3D/
```

Não realizar busca recursiva automática em todo o computador. Pesquisas amplas devem ocorrer apenas quando o usuário executar `Locate Folder`.

Estados mínimos dos assets:

```text
Online
Offline
Waiting for Sync
Syncing
Validating
Incomplete
Transfer Error
Path Conflict
Hash Mismatch
Missing Intentionally
Removed
Unknown
```

Arquivos aguardando ou realizando sincronização não podem ser apresentados como Offline.

Quando uma mídia estiver offline, o sistema deve manter:

* Clip ou Node;
* Asset ID;
* nome e último caminho;
* efeitos;
* transformações;
* crop;
* feather;
* Mapping;
* Colorize;
* parâmetros;
* demais configurações relacionadas.

A ausência do arquivo não pode causar crash, bloquear a abertura do projeto, apagar referências ou substituir automaticamente a mídia.

O Clip ou Node deve mostrar `Media Offline`, nome do arquivo perdido e ações para localizar, reconectar ou abrir o Media Manager.

Em `Locate File`, validar tipo, extensão, tamanho, hash e metadados. Caso não seja uma correspondência perfeita, mostrar a divergência e permitir substituição manual confirmada.

Em `Locate Folder`, pesquisar recursivamente na pasta escolhida usando:

```text
1. Hash exato
2. Asset ID registrado
3. Nome + extensão + tamanho
4. Nome + extensão + metadados
5. Nome + extensão
6. Nome
```

Se houver mais de uma correspondência possível, não escolher silenciosamente. Mostrar as opções ao usuário.

A reconexão de um Asset ID deve atualizar todos os Clips, Nodes e sistemas que utilizam esse mesmo asset.

Dentro do Media Manager, adicionar a ação `Collect Project`.

O Collect Project deve criar uma nova cópia portátil e independente do projeto. O projeto original não pode ser alterado.

Antes da coleta, mostrar:

* quantidade de assets;
* tamanho total;
* arquivos online;
* arquivos offline;
* arquivos internos;
* arquivos externos;
* duplicados;
* colisões;
* arquivos que não poderão ser coletados;
* mappings, layouts, controllers, presets, LUTs e assets 3D incluídos.

O usuário escolhe apenas a pasta de destino.

Estrutura de referência:

```text
NomeDoProjeto/
├── NomeDoProjeto.nstage
├── Media/
│   ├── Video/
│   ├── Images/
│   ├── ImageSequences/
│   ├── Audio/
│   ├── LUTs/
│   ├── Models/
│   └── Other/
├── Mapping/
│   ├── Layouts/
│   ├── SourceMaps/
│   ├── DisplayMaps/
│   └── mapping.json
├── Controllers/
│   ├── MIDI/
│   ├── Mappings/
│   ├── Profiles/
│   └── controllers.json
├── Presets/
├── 3D/
│   ├── Models/
│   ├── Textures/
│   └── Scenes/
├── Autosave/
├── project_manifest.json
└── asset_manifest.json
```

A estrutura deve ser adaptada ao formato real do NodeStage. Não criar arquivos ou manifestos redundantes caso essas informações já estejam corretamente persistidas no `.nstage`.

A coleta deve incluir:

* projeto `.nstage`;
* todas as mídias utilizadas;
* mappings;
* layouts;
* configurações e perfis de controladoras;
* MIDI mappings;
* presets pertencentes ao projeto;
* LUTs;
* modelos, cenas e texturas 3D;
* configurações específicas do projeto;
* manifestos necessários.

Não incluir:

* licença;
* credenciais;
* tokens;
* preferências globais;
* configurações exclusivas da máquina;
* logs;
* caches;
* arquivos temporários;
* crash dumps.

Arquivos idênticos usados em vários locais devem ser copiados uma única vez, utilizando Asset ID, hash, tamanho e conteúdo para identificar duplicidade.

Arquivos diferentes com o mesmo nome não podem ser sobrescritos. Gerar nomes físicos seguros, por exemplo:

```text
background.mov
background_a81f2.mov
```

O manifesto deve manter a relação correta entre Asset ID, nome original e caminho coletado.

Fluxo seguro de coleta:

```text
Escolher destino
→ Criar NomeDoProjeto.collecting
→ Copiar arquivos
→ Validar tamanho e hash
→ Gerar projeto coletado
→ Gerar ou atualizar manifestos
→ Validar referências relativas
→ Renomear atomicamente para NomeDoProjeto
```

A coleta deve possuir:

* progresso real por bytes;
* validação de espaço e permissões;
* cancelamento seguro;
* cópia para arquivos temporários;
* validação de integridade;
* relatório final;
* indicação clara de falha.

Uma pasta `.collecting` não pode ser tratada como projeto válido.

O sistema deve ser integrado ao Hot Backup existente. Media Manager, Asset Manager, Collect Project e Hot Backup devem compartilhar:

* Asset ID;
* hash;
* caminhos relativos;
* Project Root;
* manifesto;
* estados;
* regras de validação.

Primary e Backup podem utilizar raízes físicas diferentes. Caminhos absolutos não podem definir a identidade do arquivo.

Fluxo de sincronização:

```text
Primary registra Asset ID e hash
→ Envia manifesto
→ Backup verifica se já possui arquivo válido
→ Se possuir o mesmo hash, apenas vincula
→ Caso contrário, recebe como arquivo temporário
→ Valida tamanho e hash
→ Move atomicamente para o destino final
→ Atualiza estado para Online/Synced
```

Durante a transferência, o arquivo não pode ser aberto, marcado como Offline ou substituir uma versão válida.

Reconectar uma mídia no Primary deve atualizar corretamente o estado e a referência no Backup.

Mappings, layouts, controllers, presets e manifestos pertencentes ao projeto também devem ser sincronizados.

Ao abrir projetos antigos baseados apenas em caminhos:

* identificar referências existentes;
* agrupar referências ao mesmo arquivo;
* gerar Asset IDs;
* montar o registro central;
* preservar caminhos originais;
* criar caminhos relativos quando possível;
* preservar integralmente todas as configurações;
* salvar no novo formato apenas no próximo salvamento explícito.

Como o sistema ainda não está em produção, remover lógica antiga, código morto, registradores paralelos e resolvers duplicados. A implementação final deve possuir uma única arquitetura de assets, caminhos e sincronização.
